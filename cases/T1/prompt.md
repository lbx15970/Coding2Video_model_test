# T1｜六步功能教程

先读取登记的 Remotion skills。文档没有指定 motion-design-skill 仓库，先确认其来源；不要声称已安装未确认的 skill。

帮我做一支「Flova 灵感库怎么用」的教程，不要一次生成。每步只产出一个主文件，下一步从这个文件接着做：

1. 参考 → `spec.md`：看 `assets/targets/T1_reference.mp4`，记录节奏、第一个动作、剪辑节拍，以及为什么好看。
2. 数据 → `data.json`：每个数字旁记来源。场景文档给定：24 条方法、8 类；使用一条的方法是三步：看效果视频 → 点「在 Flova 里用」→ 回答 Agent 的几个问题后确认；本机装过的 skill 显示「已安装」，不重复装。区分用户给定事实与实际核验结果，不编造来源。
3. 故事 → `story.md`：一个观点「看到喜欢的效果，点一下就能做同款」，主角数字「3 步」，三个段落。写完先停下给我看，我说可以再做动画。
4. 动画 → `Scene.tsx`：用 Remotion 和已确认的 motion-design-skill 将每一帧写成代码；30 秒、1080×1350，帧率先确认。
5. 导演 → `timing.ts`：时序参数集中在这个文件。收到「标题晚了一拍」时，只修改对应参数行，记录前后差异；先确认当前节拍时长，不要猜。
6. 交付 → 视频：先渲染静帧，对照 `spec.md`、`data.json` 检查，然后等我同意才渲染整片。

哪里不对只改对应文件，其他保持不变。六个主交付文件是验收点；工程运行所需依赖配置单独记录，不代替主交付。

前五步文件放 `outputs/<run_id>/code/`，最终交付统一命名为 `outputs/<run_id>/videos/<run_id>_v1.mp4`；文档原名 `final.mp4` 仅作交付角色说明。
